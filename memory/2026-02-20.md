## QMD 与 clawdbot local 调研

### clawdbot 内置 local provider
- 配置 `memorySearch.provider: "local"` 可用
- 使用 node-llama-cpp + embeddinggemma-300M (328MB)
- 纯向量搜索，没有 BM25 和重排序
- 已启用并测试通过

### QMD vs clawdbot local
| | clawdbot local | QMD |
|---|----------------|-----|
| 模型 | embeddinggemma-300M | embeddinggemma + reranker + gen (~2GB) |
| 搜索 | 纯向量 | BM25 + 向量 + 重排序 |
| 集成 | 内置 | 需要代码 |

### OpenClaw QMD 后端
- OpenClaw 原生支持 `memory.backend = "qmd"`
- 代码在 `qmd-manager-*.js`，约 **700 行**
- 核心是 spawn 子进程调用 qmd CLI
- **可以搬到 clawdbot**

### 计划：搬 QMD 到 clawdbot
- 代码量小（~700行），低于1万行阈值
- 方案 A：直接 patch dist 文件（快，但 npm update 会覆盖）
- 方案 B：写独立适配层（持久）
- 宝根确认用方案 A，写 patch 脚本防覆盖

## QMD 集成到 clawdbot

### 完成
- ✅ 写了 memory-tool-qmd.js patch（~150行）
- ✅ 修改了 zod-schema 让 `provider: "qmd"` 合法
- ✅ 配置已启用 `memorySearch.provider: "qmd"`
- ✅ BM25 搜索正常工作（秒出结果）

### 问题
- ❌ `qmd query`（向量+重排序）在 ARM64 CPU 上 crash
- ❌ node-llama-cpp segfault（Bun bug）
- ❌ QMD MCP daemon 也有 bug（stateless transport）

### 当前方案
用 `qmd search`（纯 BM25）代替 `qmd query`，避免加载模型。

### Patch 文件
```
~/.clawdbot/patches/
├── apply-qmd-patch.sh      # 应用/回滚脚本
├── memory-tool-qmd.js      # patched memory-tool
├── memory-tool.js.backup   # 原版备份
├── qmd-backend.js          # QMD 后端代码
└── zod-schema.agent-runtime.js.backup
```

### 注意
- `npm update clawdbot` 会覆盖 patch，需要重新 `apply-qmd-patch.sh apply`
