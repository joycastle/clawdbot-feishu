## 🐛 Bug 修复：cron.add 参数格式错误

**时间**：2026-02-25 04:52 UTC
**发现者**：GPT 分析日志发现

### 问题现象
- 对话"回两句就没下文"，流程卡住
- 日志显示 `cron.add` 工具调用失败：`errorCode=INVALID_REQUEST`

### 根因
调用 `cron.add` 时用了错误的参数格式：
- ❌ 错误：`"schedule": "in 5 minutes"` （字符串）
- ❌ 错误：传了 `text`、`in`、`atMs` 等不符合 schema 的字段

### 正确格式
```json
{
  "action": "add",
  "job": {
    "name": "任务名称",
    "schedule": {
      "kind": "cron",
      "expr": "0 * * * *"
    },
    // 或一次性任务
    "schedule": {
      "kind": "once",
      "atMs": 1234567890
    },
    "sessionTarget": "main",  // 或 "isolated"
    "wakeMode": "next-heartbeat",
    "payload": {
      "kind": "systemEvent",  // 或 "agentTurn"
      "text": "任务内容"
    }
  }
}
```

### 推荐做法
1. **简单场景**：用 HTTP API `localhost:18797`，它会自动转换人类友好格式
   ```bash
   curl -X POST http://127.0.0.1:18797/add -d '{"job":{"schedule":"in 5 minutes","text":"..."}}'
   ```
2. **直接用 cron 工具**：必须严格按 schema 传参

### 教训
- 工具调用失败会导致流程卡住，表现为"只回开场就断"
- 遇到类似问题要检查工具调用日志

### 后续验证（05:04 UTC）

实测发现：
1. HTTP API (18797) 的人类友好格式（`"in 5 minutes"`）**并未实现**
2. 一次性任务的 kind 是 `"at"` 不是 `"once"`
3. 正确格式：`"schedule": {"kind": "at", "atMs": <timestamp_ms>}`

已更新 `memory/tools/cron-api.md` 文档。
