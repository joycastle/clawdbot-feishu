### 卡片回调 revert 问题（最折腾的部分）
- 飞书 Lark SDK WSClient 会把 EventDispatcher handler 的返回值作为 websocket 回调响应
- 如果返回 undefined → 飞书 revert 卡片到点击前状态
- 试了返回卡片 JSON / toast / 空对象，都会 revert
- **最终方案**：回调返回 toast（即时反馈"已投票"）+ debounced setTimeout PATCH（40ms 延迟）
- 原理：先让回调响应返回飞书，然后 PATCH 更新卡片，避开 revert 窗口
- 600ms → 40ms 延迟，体验几乎无感

### 关键教训
- 飞书 websocket 卡片回调的返回值格式不明确，官方文档 SPA 页面 web_fetch 抓不到内容
- PATCH API 更新卡片是可靠的，但时序要对——必须在回调响应之后
- Debounce 防止快速连点导致多次 PATCH
