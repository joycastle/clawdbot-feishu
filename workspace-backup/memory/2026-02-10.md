## 教训：URL 中文编码问题（凌晨调试惨案）

**问题**：调试 sheets-api 的 find 接口，curl 传中文参数报 400，折腾了快一小时，换了好几种方案（改 SDK 调用、换 HTTP 直接调用），最后发现是 **URL 里的中文没 encode**。

**正确做法**：
- URL 参数里有中文必须 URL encode
- `curl "...?text=宝根"` ❌
- `curl "...?text=%E5%AE%9D%E6%A0%B9"` ✅

**反思**：
1. 400 Bad Request 第一反应应该检查请求本身是否合法，不是去怀疑 SDK
2. curl 中文参数要 encode 是基础常识，不该忘
3. 调试时先用简单的英文测试排除编码问题

**以后调试 HTTP 接口的 checklist**：
1. 先用英文/ASCII 参数测试基本功能
2. 有中文/特殊字符 → URL encode
3. 400 错误 → 先检查请求格式，不是先怀疑服务端

## 游戏建造模块验收标准（黄桃分享）

### 建造区域
1. **区域关联性**：主题突出、功能明确，契合活动题材，无交叉部分
2. **差异化**：各区域主题需有较大差异，不能相近或雷同
3. **平衡性**：体量平衡，避免建造物过大过小，分布过密过疏；尽量不遮挡其他区域
4. **视觉重心引导**：
   - 区域划分：上方、下方、左边、右边（四个角）、中间区域
   - 竖屏优先级：上方 > 中间 > 下方 > 左边 = 右边
5. **故事性/叙事动线**（故事类题材）：按左侧→下方→右侧→上方展现不同叙事阶段

### 建造物
1. **主体明确**：主体建造物有代表性，能奠定区域主题基调，结构饱满有体积感；避免过于扁平或异形
2. **装饰性建造物**：
   - 弱于主体或为主体服务
   - 有区分度，大小错落分布
   - 避免抢占主体视觉、元素重叠过多、造型相近
3. **动态感**：尽量有动态感，留出动画空间；避免静态元素过多，可加入小动物互动

### 教训
1. **任何批量操作都要有幂等性**：记录已处理的目标，支持断点续传
2. **先小范围测试**：只发给 1-2 个目标验证，再扩大范围
3. **失败后先分析原因**：不要盲目重试
4. **危险操作要有确认机制**：发往多个目标前显示目标列表让人确认

## 新增：Session 广播 API (broadcast-api)

**端口：** 18799
**代码：** `/home/ubuntu/.clawdbot/extensions/feishu/src/services/broadcast-api.ts`

### API 接口

| 端点 | 方法 | 说明 |
|------|------|------|
| `/status` | GET | 服务状态 |
| `/sessions?hours=N` | GET | 获取最近 N 小时活跃的 session（hours 必填） |
| `/send` | POST | 发送到单个 session（异步） |
| `/broadcast` | POST | 批量发送到多个 session（异步） |

### 用法
```bash
# 获取活跃 session
curl "http://127.0.0.1:18799/sessions?hours=24"

# 单发
curl -X POST http://127.0.0.1:18799/send \
  -d '{"sessionKey": "...", "message": "请同步记忆"}'

# 批量
curl -X POST http://127.0.0.1:18799/broadcast \
  -d '{"targets": ["..."], "message": "请同步记忆"}'
```

### 设计要点
1. **异步非阻塞**：发送请求立即返回 `{"ok":true,"status":"queued"}`
2. **广播与筛选解耦**：/sessions 和 /send 独立调用
3. **无默认值**：hours 必须显式指定
4. **timeoutSeconds: 30**：sessions_send 需要足够时间完成（1秒太短会导致消息不送达）

### 调试教训
- sessions_send 不是瞬时的，需要：Gateway接收 → 找session → 注入消息 → agent处理
- timeoutSeconds 太短（如1秒）会导致 HTTP 返回 ok 但消息实际没送达
- 30 秒是安全值

## 新增：Session 广播 CLI（与宝根）

### 背景
约定更新广播 v3 需要发给 75 个 session，同步发会卡死当前会话。宝根建议做成异步服务。

### 实现
**文件**：`/home/ubuntu/clawd/scripts/broadcast-cli.ts`

### 用法
```bash
cd /home/ubuntu/clawd

# Dry run - 看看会发给谁
npx tsx scripts/broadcast-cli.ts --dry-run --hours 24

# 实际广播（后台执行）
nohup npx tsx scripts/broadcast-cli.ts \
  --version 3 \
  --source "宝根" \
  --message "更新内容" \
  > /tmp/broadcast.log 2>&1 &
```

### 参数
| 参数 | 说明 |
|------|------|
| `--version, -v` | 版本号（必填） |
| `--source, -s` | 来源人名（必填） |
| `--message, -m` | 消息内容 |
| `--file, -f` | 从文件读取消息 |
| `--hours, -h` | 活跃时间范围（默认 24h） |
| `--delay` | 每条间隔毫秒（默认 500） |
| `--dry-run` | 只打印目标，不发送 |
| `--skip` | 跳过的 session key（逗号分隔） |

### 特点
- 异步执行，不阻塞主会话
- 自动跳过 cron session
- 消息格式化带来源和联系人
- 每条消息间隔 500ms 避免打爆
