## 飞书项目 API 调试（与宝根）

### 背景
宝根让我测试飞书项目的工作流子任务操作：搜索需求 → 找节点 → 创建子任务 → 设排期 → 设负责人 → 标记完成

### 踩坑过程

1. **搜索接口**：`/work_item/filter` 的 `search.conditions` 参数不生效，返回的是默认排序
2. **search/params 参数格式**：需要用 `search_group` 结构，不是简单的 `search_key`
3. **name 字段操作符**：不支持 `LIKE`/`CONTAINS`，要用 `~` 做模糊匹配
4. **value 类型**：`name` 字段用 string，`owner` 等用 array
5. **子任务负责人**：需要同时设 `assignee` 和 `owners` 两个字段

- 完整跑通了子任务操作流程
- 创建了详细指南：`memory/feishu-project-api-guide.md`
- 更新了 TOOLS.md 引用

### 关键发现
- `current_status_operator` 字段可以查"我的待办"
- `~` 操作符是前后模糊匹配
- X-IDEM-UUID 每次请求必须唯一

## 飞书历史消息 CLI 上线

**问题**：跨 session 失忆，对 IM 聊天记录不可见，导致出现"确认什么？"这种尴尬场景

**解决方案**：
- 写了 `history-cli.ts`，可以通过 message_id 或 chat_id 获取会话历史消息
- 位置：`/home/ubuntu/.clawdbot/extensions/feishu/src/history-cli.ts`
- 用法：`npx tsx src/history-cli.ts --message <message_id> --count 20`

**宝根测试验证**：
- 让我给何森发请假消息，故意不让我记 memory
- 何森回复时触发新 session，但那个 session 成功拉了历史、理解上下文、给宝根发了通知
- 验证通过！工具有效

**重要经验**：
1. 感到满头雾水 → 先查 memory，没有就拉历史
2. 拉完历史要写 memory，不然下次又忘
3. 查不到就大方说缺上下文，别装懂

## 失忆自救完整闭环（宝根总结）

当收到完全没上下文的消息时：
1. 先查 memory
2. 没有 → 问对方："我断片了，但能查历史，请问是哪个会话？"
3. 对方指引 → 查那个会话历史
4. 看到任务来源 → 再查来源的会话
5. 真相大白 → 补记 memory
6. 闭环 ✅

关键点：
- 跨 session 发消息要带来源和上下文
- 别装懂，大方问
- 拉完历史要记 memory
- 隐私：不随意泄露别人聊天内容
