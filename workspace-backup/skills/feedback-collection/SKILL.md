# 反馈收集技能

> 用于收集用户反馈、调研访谈、问题征集等场景

## 触发场景

- 帮某人收集他人反馈
- 做用户调研/访谈
- 征集问题/意见
- 任何"收集信息而非解决问题"的场景

## 核心原则

### 1. 收集 ≠ 解决

**你的角色是记录员，不是顾问。**

- ❌ 收到问题后立即给解决方案
- ✅ 收到问题后确认收到，引导说得更清楚

### 2. 先确认，再引导

收到反馈后：
1. 发个表情确认（✅/👌）
2. 引导追问，让问题更具体
3. 记录完整要点

### 3. 引导式追问

用户说的往往是"症状"，你要帮他们挖出"病因"。

**追问模板**：
- "能举个例子吗？比如你让它做什么，它跑去做了什么？"
- "具体是什么情况下会这样？"
- "你现在是怎么用的？卡在哪一步？"
- "这个问题多久出现一次？"

### 4. 不遗漏要点

记录时要完整，包括：
- 使用场景（做什么）
- 遇到的问题（什么不好用）
- 想知道的（有什么疑问）
- 具体例子（如果有的话）

## 反馈收集模板

### 开场（主动发起调研时）

```
我在帮 XX 收集关于 YY 的问题，想占用你 2 分钟：

1. 你平时用 YY 做什么？
2. 有没有遇到过让你觉得"这玩意儿不行"的时刻？
3. 有没有什么想知道但还没搞明白的？

随便聊几句就行，不用写小作文 😄
```

### 追问示例

**用户说**："任务复杂后不遵守 prompt"

**追问**："能举个例子吗？比如你让它做什么，它跑去做了什么？"

---

**用户说**："对遗留代码库缺乏理解"

**追问**："被什么误导？是它读错了代码结构，还是被老注释/过时文档带偏了？"

---

**用户说**："想知道怎么异步协作"

**追问**："你现在是怎么用的？是开着终端等它跑完，还是让它后台跑、回来看结果？具体卡在哪一步？"

### 记录格式

```markdown
## [用户名] 反馈

**使用场景**：
- 场景1
- 场景2

**遇到的问题**：
1. 问题描述
   - 具体例子（如果有）
2. 问题描述
   - 具体例子

**想知道的**：
- 疑问1
- 疑问2
```

## 常见错误

### ❌ 跑偏成顾问

用户反馈问题 → 你立刻给了一堆解决方案

**正确做法**：确认收到 → 引导说清楚 → 记录下来

### ❌ 没有追问就记录

用户说"不好用" → 你直接记"不好用"

**正确做法**：追问"哪里不好用？能举例吗？"

### ❌ 遗漏要点

用户说了三件事 → 你只记了一件

**正确做法**：全部记录，不确定的回头确认
