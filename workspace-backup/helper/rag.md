# RAG 知识库检索

> 🧪 **实验性功能** — 目前仅索引了少量文档，不宜大规模使用

---

## 能做什么

我可以从已索引的飞书文档中检索相关内容来回答问题。

**适用场景：**
- 查公司内部文档（已索引的）
- 找特定玩法/功能的设计说明
- 跨多个文档查找相关信息

**目前已索引：**
- 特殊玩法文档（圣诞节、情人节、花园、动物折纸、老虎机）

---

## 如何使用

### 直接问我

问涉及已索引文档的问题，我会自动检索：

> "情人节玩法的小鸟放置算法是什么？"
> "花园玩法的 Bingo 条件有哪些？"

### 让管理员索引新文档

如果需要索引新的飞书文档，找管理员执行：

```bash
cd ~/.clawdbot/extensions/feishu/scripts/rag
python3 index.py --url "https://xxx.feishu.cn/wiki/xxxtoken" --advanced
```

## 工作原理

### 基础流程

```
飞书文档 → 切成小块 → 转成向量 → 存入数据库
                                    ↓
用户提问 → 转成向量 → 找最相似的块 → 组合回答
```

1. **文档切片**：把长文档切成 500 字左右的小块，便于精准匹配
2. **向量嵌入**：用 AI 模型（bge-small-zh）把文本转成数字向量
3. **向量检索**：用户提问时，找出语义最相似的几个文档片段
4. **组合回答**：把相关片段作为上下文，让我来回答问题

### Advanced 模式（摘要优先）

普通 RAG 的问题：文档切得太细，有时候只匹配到局部内容，丢失全局视角。

我们的解决方案是**双层索引**：

```
┌─────────────────────────────────────────┐
│  摘要层：每篇文档一个 300 字摘要        │  ← 先搜这里，找到最相关的文档
├─────────────────────────────────────────┤
│  详情层：文档切片（500 字/块）          │  ← 再搜这里，找到具体段落
└─────────────────────────────────────────┘
```

**好处：**
- 宏观问题（"对比几个玩法的风格"）→ 先看摘要，不会迷失在细节里
- 具体问题（"小鸟距离限制是多少"）→ 深入详情，找到精确答案

---

## 注意事项

⚠️ **实验性功能，有以下限制：**

1. **索引范围有限** — 只有被手动索引的文档才能检索到
2. **不是实时同步** — 文档更新后需要重新索引
3. **检索不是万能的** — 问题太模糊可能找不到相关内容
4. **不要批量索引** — 大量索引会消耗资源，目前不建议

---

## 没索引的文档怎么办？

直接给我飞书文档链接，我可以实时读取：

> "帮我看看这个文档：https://xxx.feishu.cn/wiki/xxxtoken"

实时读取适合一次性查阅，RAG 适合反复查询的常用文档。
